## macOS FFmpeg 경량판 자막 출력 호환성 (2026-10-22 dev)

- Homebrew 일반 `ffmpeg`에서 `ass` 필터가 빠진 경우에도 MP4 자막 번인을 **포기하지 않습니다**. `ffmpeg-full`의 libass 실행 파일이 있으면 우선 사용하고, 없으면 Electron의 로컬 Canvas로 **한글·영어 자막/Hook을 투명 PNG 타임라인**에 그려 FFmpeg `overlay` 필터로 합성합니다. 이 대체 경로는 libass나 FFmpeg drawtext를 필요로 하지 않습니다.
- 한 화면의 동시 자막과 Hook을 합성한 프레임 이미지를 이어 붙인 단일 FFconcat 입력을 사용하며, 시간이 비어 있는 구간도 보존합니다. 기존 FFmpeg 오디오·크롭/블러·MP4 설정, 선택된 스타일 ID/데이터를 유지합니다.
- Canvas 스타일은 ASS의 근사 구현으로 **글꼴/테두리/줄바꿈이 완전히 같지 않을 수 있습니다**. macOS 한글 실제 출력 확인이 필요합니다. `ffmpeg-full` 설치는 여전히 최고 충실도의 ASS 출력에 권장하지만 필수는 아닙니다.

## AG2 음성 인식 구간 조정 UX 보완 (2026-10-22, dev)

- 과거 `실제 대사로 구간 다듬기`는 인식 결과가 사실인 것처럼 보이고 각 행에 IN/OUT만 있어 동작 확인이 어려웠습니다. **`음성 인식 결과로 시작·끝 맞추기`**로 명확히 변경하고 현재 시작/끝·길이, 각 대사의 시작/끝 시각(0.01초 단위), **▶ 듣기(원본 확인)**, **IN 시작 / OUT 끝** 버튼과 적용 여부 표시를 제공합니다.
- IN/OUT 선택은 그 시점으로 원본 플레이어를 이동하고 현재 클립 구간을 갱신합니다. 듣기는 임시 구간에서만 재생하며 클립 데이터를 변경하지 않습니다. 같은 문장이 짧은 간격으로 3번 이상 반복 인식되면 검토 경고를 표시하지만 실제 반복 발화 가능성이 있어 **전사나 기존 클립을 삭제·변형하지 않습니다**.
- 기존 Whisper 분석/추천과 사용자 승인·저장 방식은 유지합니다. 유튜브 실영상의 인식 정확도 및 재생 동작은 사용자 Mac 실기 확인이 필요합니다.

## dev 신규 구현: AG2 YouTube 원본 분석 및 클립 자동 추천 (2026-10-22)

**원본 URL → 원본 승인 → 02 클립 → 'AI 음성 분석 · 클립 자동 추천'**을 누르면 기존 공개 YouTube 원본 가져오기/캐시 경로와 `whisper.cpp`를 사용합니다. 처음 분석은 선택한 언어(자동/한국어/영어)로 원본을 9분 이하 구간으로 나눠 로컬 전사하고, 실제 대사의 질문·반전 표현·문장 끝·발화 밀도 등을 분석해 **가능한 만큼 최대 8개**의 클립 후보를 추천합니다. 대사가 충분하지 않으면 5개를 억지로 만들지 않습니다. 전체 길이 중 **첫 60분**까지만 자동 분석하며, 긴 영상은 수동 탐색을 병행합니다.

후보 카드에는 **추천 이유·실제 인식 대사·시작/끝 시각·길이·구간 재생**이 표시됩니다. 체크박스로 여러 후보를 선택해 각각 독립된 클립으로 추가한 후 IN/OUT을 숫자 또는 **전사 문장의 IN/OUT 버튼**으로 다듬고 승인할 수 있습니다. **더 짧게/더 역동적으로** 모드는 저장된 전사를 재활용해 다른 후보를 계산합니다. 명시적 '원본 재분석'으로 Whisper를 다시 돌릴 수 있으며 진행률, 취소, 오류 복구, 캐시 재사용을 지원합니다. 기존 사용자 클립은 재추천해도 삭제·덮어쓰지 않습니다.

이 기능은 **로컬 Whisper 음성 인식 + 설명 가능한 휴리스틱 추천**입니다. 성과 점수·시청률 예측·LLM이 생성한 내용이라고 포장하지 않습니다. 현재 장면 비주얼 자동 추천/원격 LLM 후보 재정렬/무음 게임·액션 중심 추천은 구현 전입니다. 오디오 트랙이 없거나 대사 부족·네트워크/모델 문제 시 **직접 클립 선택**이 계속 가능합니다. 원본의 권리, 플랫폼 이용약관, 업로드 승인은 별개입니다.

**설치:** macOS에서는 `brew install yt-dlp ffmpeg whisper.cpp`로 실행 도구를 준비한 후, 앱의 클립 단계에서 **기본 Whisper 다국어 모델 설치**를 선택합니다. 모델 설치를 제외하면 영상/대사 분석은 로컬에서 수행합니다. `docs/AG2_CLIP_RECOMMENDATIONS.md`에 실행·설계·수용 절차를 기록했습니다. Mac/Windows 실영상 추천·A/V·품질은 아직 사용자가 직접 확인해야 하며, 오프라인 합성 테스트/CI 통과와 구분합니다.

## 현재 dev 구현: AG1 단계별 제작 마법사 (2026-10-22)

기본 모드는 **단계별 제작**입니다. 원본 URL 입력 → 실제 영상 길이 확인 → 오른쪽 플레이어 재생 위치에서 30초짜리 수동 클립 후보 추가 → 구간/이름 미세 수정 → 화면(9:16 스타일 4종), 자막(8종 카드/전사 재사용/Hook), 소리(원본 유지), CTA(OFF), 검토 → MP4 출력 순으로 진행합니다. 매 단계 승인/이전/선택적 건너뛰기가 가능합니다.

**고급 편집**을 누르면 기존 3열 소스/클립/자막/출력/게시 패널이 나타납니다. 둘은 같은 프로젝트/클립을 사용합니다. 단계 위치, 제안 및 승인 데이터, 클립별 상태는 프로젝트 JSON에 저장되고 이전 프로젝트 파일은 손실 없이 읽습니다. 클립 구간·자막·해상도 변경 후 관련 단계는 `needs_review`로 돌아갑니다.

클립 단계의 재추천은 작동하지만, 화면·자막 스타일·사운드·CTA의 '다시 생성'은 각 생성기가 연결될 때까지 **비활성화**되어 있습니다. AI가 생성하지 않은 수동 클립이나 중앙 크롭을 AI 추천이라 표시하지 않습니다. 오른쪽 YouTube 플레이어는 **원본 참고**이며 최종 FFmpeg 9:16 합성 미리보기가 아닙니다. 코드/테스트 상태와 Mac/Windows 사용자 수용 차이는 [AG1 구현 현황](docs/IMPLEMENTATION_STATUS.md)을 참고하세요.

개인용 ShortFab 앱에서 **기존 YouTube 영상 링크를 입력하여 클립을 선택하고 MP4 익스포트까지 성공**했다고 사용자가 확인했습니다. 따라서 과거의 **“YouTube는 미리보기만 가능 / 직접 MP4 익스포트 불가능”** 문제는 해당 실사용 환경에서 해결된 것으로 기록합니다.

이는 기능의 **최소 유효 흐름(P0)**에 대한 실제 수용 확인입니다. 다른 영상/국가/접근 제한 사례, 3개 서로 다른 클립의 연속 출력, 세부 A/V 싱크 및 크롭, 자동 업로드·설치 패키지 검증은 포함하지 않습니다. [진행 현황표](docs/IMPLEMENTATION_STATUS.md)에 확인 근거를 구분해 정리했습니다.

## 목표 사용자 흐름 · v2.0

**YouTube URL 입력 → AI 원본 분석 → 클립 후보 추천/선택·조금 수정 → 자동 레이아웃/수정 → 자동 자막/수정 → 나레이션·음악 제안/수정 → CTA 제안/수정 → 최종 합성 검토 → MP4 출력 → 권리·계정 확인 후 별도 승인 게시.**

모든 단계에서 사용자는 '이대로 사용', '조금 수정', '다시 생성'을 고릅니다. AI가 수정된 내용과 이미 승인한 값을 무단으로 덮어쓰지 않습니다. 고급 타임라인 편집은 기본 경로에서 숨기고 필요 시 진입합니다. **8단계 UI와 음성 기반 클립 추천 코드는 구현되었고, 자동 스마트 레이아웃·TTS·CTA 등은 아직 구현되지 않았습니다.**

- **현재 기술 기반:** Electron/React/TypeScript와 로컬 FFmpeg·whisper.cpp; 개인용 YouTube URL→클립→MP4 기본 흐름 실기 성공.
- **입력 우선순위:** YouTube URL 주력, 로컬/권리자 소스는 보조. 공개 URL과 다운로드/게시 허가는 별개.
- **스타일과 CTA:** 화면 단계 내 AI 추천 및 사용자 승인형. 동적 Trend Studio/브랜드 카탈로그는 차후 고도화.
- **출력/게시:** MP4와 외부 게시를 구분하고, 자동 업로드는 별도 승인 없이는 수행하지 않음.

## 현재 구현된 수동 클립 탐색 (YF-0 코드 구현, 추후 Advanced Edit)

- **새 프로젝트의 시작 탭은 YouTube**입니다. HTTPS YouTube 동영상 URL을 붙여넣고 공식 IFrame 플레이어에서 재생/구간 이동/IN·OUT을 지정할 수 있습니다. YouTube 동영상 길이를 확인한 후 **후보 추가**로 최대 100개의 클립(로컬 클립 포함)을 저장할 수 있으며 선택 구간 반복도 지원합니다.
- 후보는 `source: youtube`로 프로젝트에 저장되므로 로컬 원본을 연결하지 않아도 앱을 다시 열어 편집을 계속할 수 있습니다. 로컬 파일 클립은 별도 `source: local`로 유지합니다.
- **클립 직접 출력**: YouTube 영상의 IN/OUT 후보를 저장하고 **MP4 익스포트**를 누르면 yt-dlp 공개 미디어 가져오기 및 FFmpeg 세로형 렌더를 실행합니다. 도구가 없으면 설치 안내를 표시하며, 비공개·DRM·접근 제한 영상은 지원하지 않습니다.

## 현재 구현된 고급 편집 화면 · Phase 2 컴팩트 워크스페이스 (Advanced Edit)

- 데스크톱 앱의 작업 공간은 창 높이에 맞춰 고정합니다. **왼쪽 소스/클립 패널과 오른쪽 작업 패널만 개별 스크롤**하므로, YouTube 게시 폼이나 작업 이력이 많아도 가운데 9:16 미리보기와 타임라인이 화면 밖으로 밀리지 않습니다.
- 오른쪽 패널은 **MP4 익스포트 / YouTube 게시 탭**으로 분리했습니다. 익스포트가 완료되면 YouTube 탭으로 이동하고, 필요한 경우 다시 MP4 탭으로 돌아올 수 있습니다.
- 작은 웹 화면에서는 패널을 세로로 쌓아 스크롤할 수 있습니다. 현재 데스크톱 수용 확인은 별도로 진행 중입니다.

## 개발 원칙

1. **앞으로 신규 기능은 AI 추천 우선의 8단계 승인 UX를 기준으로 개발합니다.** 기존 수동 편집 경로는 회귀 방지/고급 편집으로 유지합니다.
2. 각 프로젝트는 **비파괴 편집 데이터**로 저장됩니다. 스타일의 **버전 스냅샷**과 개별 속성 저장은 후속 Phase 1 개발 범위입니다.
3. 렌더, SNS 업로드, SNS 게시 완료는 서로 다른 단계입니다. 외부 게시 작업에는 별도의 사용자 확인이 필요합니다.
4. 스타일 카탈로그는 검증·호환성 검사·롤백 가능해야 합니다. 동적 자바스크립트나 미승인 바이너리 배포 방식은 사용하지 않습니다.
5. 플랫폼 API·저작권·음원·폰트·AI 음성 조건을 확인할 수 없으면 안전한 대체 경로(로컬 파일로 내보내기 등)를 제공합니다.

## 로컬 개발 시작

```bash
npm install
npm run dev
```

Mac에서는 먼저 `brew install yt-dlp ffmpeg`를 실행합니다. YouTube 링크를 입력하고 구간을 선택한 후 **MP4 익스포트**를 누르세요. 로컬 파일 입력도 유지됩니다. yt-dlp, ffmpeg 및 ffprobe를 실행할 수 있어야 합니다. `npm run check`, `npm run lint`, `npm test`, `npm run build`도 제공됩니다. 상세한 설치·제약사항은 [DEVELOPMENT.md](docs/DEVELOPMENT.md)를 참고하세요.

프로젝트는 앱 사용자 데이터 폴더의 `projects/*.json`에 자동 저장됩니다. 프로젝트 선택기로 이전 프로젝트를 다시 열고, 원본 파일을 옮긴 경우 **원본 파일 재연결**을 선택하세요. 원본 파일은 프로젝트 JSON에 복사되지 않습니다.

**편집 중 자동 저장:** 클립 이름을 지우거나 IN/OUT 값을 입력하다 일시적으로 유효하지 않은 상태가 되면 Electron 저장 요청을 보류하고 `수정 필요 · 저장 대기`를 표시합니다. 올바른 이름·구간·해상도를 다시 설정하면 자동 저장이 재개됩니다. 0.2초 최소 구간 검증은 저장·원본 매핑·렌더 요청에 같은 소수점 오차 허용치를 적용합니다. 잘못된 상태에서 프로젝트 이동/MP4 익스포트는 차단되어 편집값이 유실되지 않습니다.

YouTube 업로드 개발 시 Desktop OAuth 클라이언트 ID를 `SHORTFAB_GOOGLE_CLIENT_ID`로 설정하고, OAuth/OS 암호화 저장소 조건을 충족해야 합니다. 자세한 단계와 실계정 검증 체크리스트는 [Phase 2 YouTube 문서](docs/PHASE2_YOUTUBE.md)를 참고하세요.

실험용 앱은 ffmpeg/ffprobe를 직접 번들링하지 않습니다. Electron vs Tauri, 코드 서명과 최종 배포는 Phase 0 검증 후 확정합니다.

## 기존 자막 편집 기능 · Phase 1 (2026-10-22 코드 구현, 향후 자막 단계에 통합)

클립 후보 아래 **자막 편집**을 열면 자막을 구간별로 직접 입력하고, **기본 흰색 / 강조 노랑 / 미니멀 / 배경 박스** 네 가지 스타일을 선택할 수 있습니다. 시간은 원본 영상의 절대 시각이 아니라 **선택한 클립 IN 기준(0초부터)**입니다. 최대 30개/클립, 100자/자막이며 겹치는 자막, 잘못된 시간·빈 텍스트는 자동 저장과 익스포트를 보류합니다.

편집값은 기존 프로젝트 JSON에 선택 필드로 안전하게 저장됩니다. MP4 출력 시 **libass가 있으면 ASS 자막으로**, libass가 없는 일반 FFmpeg에서는 **Electron Canvas PNG + overlay** 대체 경로로 자막을 합성합니다. 자막이 없는 클립은 이전 렌더 경로를 그대로 사용합니다. UI의 자막 표시는 출력 위치를 간략하게 보여주는 참고용으로, 공식 YouTube 원본 화면과 최종 9:16 합성 프레임이 동일한 미리보기는 아닙니다. 한국어 글꼴은 실행 OS의 설치 글꼴과 FFmpeg/libass 폰트 설정에 영향을 받으므로 실기 확인이 필요합니다.

자막/스타일을 수정한 뒤에는 **기존 MP4를 재사용해 바로 YouTube 게시하지 못하도록** 출력물과 자막 구성 일치 여부를 확인합니다. 자동 STT는 로컬 Whisper.cpp 연동 코드를 추가했으며 실제 모델/음성 수용은 별도입니다. 원격 스타일 카탈로그와 나레이션·CTA는 아직 미구현입니다. 테스트는 `src/shared/subtitles.test.ts`, `electron/subtitles.test.ts`, `electron/render.test.ts`에서 검증합니다.

## FFmpeg 자막 렌더·Whisper 모델 설치 문제 해결 (2026-10-22 수정)

- **`No option name near 'captions.ass'`**는 macOS에서 FFmpeg에 `ass`/libass 필터가 빠져 있을 때 발생할 수 있습니다. 이제 자막 출력 전에 필터를 검사하고 Homebrew의 `ffmpeg-full` 실행 파일이 설치돼 있다면 자동 선택하며, 없으면 Canvas 오버레이로 출력합니다. 설치 명령: `brew install ffmpeg-full`. 별도 경로를 사용할 때는 `SHORTFAB_FFMPEG_PATH`를 해당 바이너리로 지정하세요. 자막 없는 MP4는 기존 FFmpeg로 그대로 출력됩니다.
- **Whisper 모델 URL 허용 오류**: 공식 Hugging Face가 제공하는 지역별 `*.hf.co` CDN/Xet 리다이렉트를 허용합니다. 여전히 HTTPS만 허용하고 외부 다운로드 모델의 파일 크기와 고정 SHA-256을 검사합니다. 다운로드 실패/중단 시 손상 파일은 설치하지 않습니다.
- 수정 코드는 `dev`에 반영한 것이며, 실제 사용자의 macOS FFmpeg 구성 및 Whisper 148MB 다운로드 재확인은 별도입니다. [로컬 STT 안내](docs/STT_LOCAL.md) · [AG4 자막](docs/AG4_CAPTIONS.md).

## Whisper 설치 진행 화면 개선 (2026-10-22)

- 02 클립·04 자막·고급 편집이 하나의 모델 설치 상태 UI를 공유합니다. 설치를 누르면 **기존 파일 확인 → 원격 서버 연결 → 다운로드(%, 받은 MB / 전체 MB) → 검증 → 로컬 등록 → 완료**가 보입니다.
- 서버 응답 대기·검증 중처럼 내려받은 바이트가 변하지 않는 단계도 별도 안내와 활동 표시, 경과 시간을 제공합니다. 다운로드 중 데이터가 일정 시간 들어오지 않으면 기다리는 시간을 표시하고 **취소**할 수 있습니다.

## AI 자동 자막 생성 (Phase 1 코드 추가 · 2026-10-22)

기존 **자막 편집** 패널에서 로컬 Whisper 음성 인식으로 선택한 클립의 자막 구간을 생성할 수 있습니다. 한국어 / 영어 / 언어 자동 감지 선택을 지원하며, 생성 결과는 **기존 수동 자막과 같은 편집·자동 저장·4개 스타일·FFmpeg 자막 번인** 파이프라인으로 연결됩니다. 생성 결과 적용 전 기존 자막 덮어쓰기 확인을 요청하며 취소/실패 시 기존 자막은 유지됩니다.

**최초 사용 준비:** Mac에서는 `brew install whisper.cpp ffmpeg`로 실행 파일을 설치합니다. 자막 편집 패널에서 **기본 한국어·영어 모델 설치 (약 148MB)** 버튼을 누르면 공식 Hugging Face의 다국어 GGML `ggml-base.bin` 모델을 한 번 내려받고, 지정된 크기·SHA-256 검증을 통과한 뒤 앱 로컬 설정에 연결합니다. 다운로드 진행 표시/취소, 검증 성공한 캐시 재사용을 지원합니다. **사용자 클릭 전 다운로드하지 않습니다.** 이미 가진 모델은 **다른 GGML 모델 파일 선택…**으로 연결할 수 있습니다. 영문 전용 `.en` 모델은 한국어 인식에 적합하지 않습니다. Windows는 `whisper-cli`와 `ffmpeg`를 PATH에 설치하거나 `SHORTFAB_WHISPER_PATH`로 실행 파일을 지정하세요.

선택 클립은 **10분 이내**, 30개 자막 / 자막당 100자 제한입니다. YouTube는 기존 개인용 공개 미디어 캐시 또는 연결된 권리자 원본을 이용합니다. 음성 파일은 임시 디렉터리에 만들어 처리 뒤 삭제하며, 외부로 보내지 않습니다. **최초 모델 다운로드만** 인터넷 연결을 사용합니다. 모델 주소는 공식 배포 저장소로 제한하고 파일 SHA-256이 일치하지 않으면 거절합니다. 모든 URL/영어·한국어 실제 음성 성능은 별도 수용해야 합니다.

[설치·문제 해결 및 테스트 안내](docs/STT_LOCAL.md).

## YF-1 · 권리자 제공 원본 연결 (2026-10-22)

YouTube URL에서 구간 후보를 만든 뒤 **권리자 이름·허가 증빙 참조·발췌/변형 허가**를 확인하고, 권리자가 제공한 로컬 영상 파일을 선택할 수 있습니다. 선택적 SHA-256과 시작 오프셋, 사용권 만료일 및 YouTube 재게시 허가를 입력할 수 있습니다. 파일 체크섬·길이/시간 범위를 검증한 뒤 해당 클립을 기존 FFmpeg MP4 렌더에 사용할 수 있습니다. 같은 videoId로 저장한 원본은 다음 프로젝트에서 자동 매칭됩니다.

파일 무결성 확인은 YouTube 영상과의 내용 동일성 또는 실제 라이선스 진위를 보증하지 않습니다. **개인용 직접 출력 경로에서는** 별도 원본 파일 없이 접근 가능한 공개 YouTube 링크로 MP4 출력이 가능하며 사용자 실기 성공을 확인했습니다. 이 절의 YF-1은 **별도 허가 원본 바인딩** 경로로서 실제 파트너·권리 검증 및 실영상 3개 출력은 아직 미완료입니다. [YF-1 기술·수용 테스트](docs/YF1_AUTHORIZED_SOURCES.md).

## YF-1 · 승인 HTTPS 클라우드 원본 가져오기 (2026-10-22)

권리자가 제공한 직접 미디어 URL(.mp4/.mov/.mkv/.webm/.m4v)도 원본으로 연결할 수 있도록 개발했습니다. YouTube 영상의 구간 후보를 먼저 선택하고 권리자/계약 증빙 및 편집 허가를 입력한 다음, **권리자 SHA-256 체크섬(필수)**과 HTTPS 원본 URL을 입력해 **클라우드 원본 다운로드·검증·연결**을 누릅니다. 다운로드 성공 시 개인 앱 데이터 폴더에 원본을 보관하고, 이후 videoId에 따라 자동 재연결합니다.

파일 호스트는 앱 개발자가 환경변수 `SHORTFAB_APPROVED_SOURCE_HOSTS=assets.creator.example,cdn.partner.example`에 사전 승인해야 합니다. **임의 URL/YouTube 영상 스트림 다운로드를 지원하지 않으며**, 리다이렉트·사설 IP·해시 불일치·다운로드 초과를 거절합니다. 최대 2 GiB, 전체 다운로드 제한시간 120초입니다. URL의 서명·토큰이 로그나 프로젝트 JSON에 저장되지 않도록 설계했습니다.

이는 허가된 원본 파일 취득용 기초 어댑터입니다. 실제 파트너 권한·동영상 동일성 및 3개 MP4 실제 생성/OS 설치 테스트는 아직 수행하지 않았습니다. 상세 사용법과 검증 게이트는 [YF-1 원본 연결 문서](docs/YF1_AUTHORIZED_SOURCES.md)를 참조하세요.



## YF-2 · YouTube 영상 ID에서 승인된 원본 자동 탐색

승인 파트너가 구성된 ShortFab에서는 YouTube URL 입력/공식 플레이어 탐색 후 **“YouTube ID로 승인 원본 자동 찾기”** 버튼을 사용할 수 있습니다. 파트너의 영상 ID 카탈로그에서 **Ed25519 서명된 원본 정보(다운로드 위치·SHA-256·사용권 범위/만료)**를 조회하고, 서명·영상 ID·호스트/파일 검증을 거쳐 자동 연결합니다. 기존 로컬/직접 링크 연결도 유지됩니다.

운영자는 `SHORTFAB_APPROVED_SOURCE_HOSTS`, `SHORTFAB_PARTNER_CATALOG_ENDPOINT`, `SHORTFAB_PARTNER_PUBLIC_KEY_B64`를 설정해야 합니다. 실제 파트너 API/계약/실영상 원본이 없는 기본 앱에서는 자동 검색 버튼이 비활성화됩니다. 카탈로그 서명은 파일 매핑에 대한 **권리자 주장 진위**를 확인할 뿐 YouTube 영상 프레임 일치나 실제 권리 관계를 독립적으로 증명하지 않습니다.

[파트너 API·설정·검증 항목](docs/PARTNER_CATALOG.md) · [개발 로드맵](docs/ROADMAP.md). **파트너 실연동·OS 실기·실제 3개 영상 익스포트는 미검증**.
