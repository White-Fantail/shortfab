# ADR-0001: 로컬 우선 하이브리드 제품 아키텍처

- Date: 2026-10-22
- Status: **제안 승인된 제품 방향 / 구체 기술 검증 대기**

## 맥락

영상은 용량이 크고 렌더링에 CPU/GPU·스토리지 비용이 듭니다. 순수 SaaS에서는 모든 원본을 업로드해야 하는 부담이 있습니다. 반대로 순수 데스크톱은 원격 프리셋 업데이트, AI 연동, SNS OAuth 및 예약 게시를 제공하기 어렵습니다.

## 결정

1. 1차 사용자 경험은 **로컬 우선 데스크톱 앱**으로 설계하고, 클라우드 서비스는 AI/원격 스타일 카탈로그/계정 연동/게시 같은 선택적 기능을 제공한다.
2. 편집 상태는 플랫폼 중립적 Composition/RenderManifest로 표현한다. 로컬과 향후 클라우드 렌더러는 동일 명세를 처리할 수 있도록 인터페이스를 분리한다.
3. 원격 스타일은 선언형 데이터·서명·버전 고정·검증·롤백 방식을 채택한다.
4. YouTube URL 탐색과 사용자 제공 렌더 원본을 별개로 처리한다.
5. 플랫폼별 실제 게시와 외부 업로드는 최종 사용자 승인 후 별도 작업으로 실행한다.

## 아직 확정하지 않은 사항

- Electron vs Tauri (우선 후보 Electron + React + TypeScript)
- STT/TTS/AI 추천 공급자 및 실행 위치
- 클라우드 배포 사업자·저장소·요금·예약 게시 작업자
- GPU 인코딩 최적화와 FFmpeg 배포/라이선스 검토
- 각 SNS API의 실제 앱 심사/승인 범위

## 결과

- 로컬에서 단독으로 영상 선택과 MP4 렌더가 가능해야 함.
- 온라인 카탈로그가 없어도 마지막으로 검증한 스타일을 계속 사용 가능해야 함.
- 클라우드 기능 장애·토큰 만료가 사용자 로컬 프로젝트를 손상시키지 않아야 함.
- 제품 데이터 구조와 테스트를 UI 프레임워크나 한 AI 공급자에 종속시키지 않아야 함.

## 검증 필요

macOS/Windows 패키징, 접근성/로컬 작업 속도, 프록시/4K 렌더 성능, 로그인/OAuth 콜백, 보안 저장소, API 권한, 원격 카탈로그 신뢰체계, 비용 모델을 Phase 0에서 검증하고 ADR을 업데이트합니다.
