## 0. 제품 정의

ShortFab은 **이미 YouTube에 존재하는 긴 영상**에서 재미있거나 가치 있는 구간을 찾아 새 숏폼으로 재구성하는 **YouTube URL-first 클리핑 도구**다. 주 사용자는 원본을 직접 촬영하거나 로컬 MP4를 보유하지 않는다. YouTube 링크로 탐색·클립 후보 저장을 시작하고, 편집·배포 권리와 취득 권한이 있는 소스는 인코딩 가능한 원본을 연결해 자막·나레이션·CTA를 적용한 MP4로 만든다. **임의 공개 YouTube URL의 보편적 MP4 추출을 이미 지원하거나 보장한다는 뜻은 아니다.**

**제품 원칙**
1. **YouTube 영상 URL이 주 입력**이다. 원본 촬영·파일 준비를 요구하는 워크플로 대신 전문가용 타임라인보다 빠른 선택형 클리핑을 기본으로 한다.
2. 자동화는 추천·초안까지만 담당하고, 게시 전에는 반드시 사용자가 승인한다.
3. 기본 기능은 로컬에서 동작하며, 클라우드는 선택적 편의/AI/연동 계층이다.
4. 동일한 원본에서 여러 클립·여러 출력 비율·여러 언어 버전을 재활용한다.
5. **링크→새 MP4 제작은 핵심 제품 목표이자 미해결 개발 게이트**다. 공식 API가 범용 다운로드를 제공하지 않으므로 권리자 제공 원본·승인 저장소를 우선 연결하고, 정책을 우회하는 추출/스크래핑을 기본 제품 의존성으로 두지 않는다.
6. 실수로 게시·재게시되지 않게 렌더/업로드/발행을 분리하고 이력과 재시도를 둔다.
7. 유행하는 편집 스타일은 원격 카탈로그에서 계속 공급하되, 새 스타일의 *발견*과 기존 프로젝트의 *자동 변경*은 별개로 취급한다.
8. CTA는 마지막 단계에서 간단히 선택하고 수정할 수 있어야 하며 플랫폼별 실제 클릭 경로와 안전 영역을 반영한다.

## 1. 대상 사용자와 핵심 사용 사례

- **기존 YouTube 영상을 활용하는 클립 큐레이터(주 사용자):** 직접 촬영하지 않은 영상의 URL을 입력해 의미 있는 장면을 탐색하고, 이용 권리를 확보한 뒤 새 숏폼을 만든다.
- 개인 크리에이터: 허가받은 라이브/브이로그/인터뷰에서 재미있는 장면을 3~10개의 숏폼으로 추출.
- 교육·지식 크리에이터: 강의에서 주제별 핵심 설명을 독립적인 짧은 영상으로 편집.
- 팟캐스터: 대화 하이라이트 탐색, 화자 추적 크롭, 큰 자막 제작.
- 매장·마케팅 담당자: 제품 설명·행사 영상을 템플릿으로 재활용하고 반복적으로 배포.
- 소규모 팀/에이전시(후속): 브랜드 템플릿, 승인, 다계정, 예약 배포.

**핵심 JTBD:** “내가 원본을 직접 제작하지 않아도 YouTube 링크 하나로 시작해 유용한 구간을 고르고, 사용 권한이 있는 영상이라면 파일을 일일이 준비하지 않고 MP4 숏폼을 만들고 싶다.”

**비목표(초기):** CapCut/Premiere급 고급 타임라인, 저작권 탐지 완전 자동화, 광고수익 보장, 외부 채널 영상의 무단 자동 다운로드, 복잡한 협업·정산.

## 3. 핵심 사용자 경험

### 3.1. 마법사(Quick Create) + 고급 편집(Advanced Edit) 이중 UX

- Quick Create: `소스 > 구간 > 화면 > 스타일(자막/오디오) > CTA > 내보내기/게시` 여섯 단계. 각 단계는 오른쪽 프리뷰에 즉시 반영되며 이전 단계로 돌아와도 설정 유지.
- Advanced Edit: 타임라인, 컷 추가/삭제/순서 변경, 자막 단어 단위 시간 수정, 오디오 트랙, 키프레임 대신 간단한 얼굴 포커스·크롭 위치 조정. 고급 편집으로 바꿔도 간편 모드 설정이 소실되지 않음.
- 프로젝트 자동 저장, 되돌리기/다시 실행, 프리셋/최근 설정, 전체 화면 프리뷰, 키보드 단축키(J/K/L, I/O, Space, 좌우 프레임 이동).

### 3.2. 화면 구성

1. **홈/라이브러리**: 새 프로젝트, 최근 작업, 처리 상태, 소스별 생성 클립, 템플릿.
2. **소스**: YouTube URL / 로컬 파일 / 연결된 저장소 / 이전 미디어. 링크 미리보기와 원본 파일 연결 상태를 명확하게 보여줌.
3. **클립 발견**: 원본 플레이어, 장면/파형/대본 탐색, 타임라인 마커, AI 후보 카드와 근거, 중복 후보 정리.
4. **숏폼 편집**: 중앙 세로 프리뷰, 왼쪽 클립 목록, 오른쪽 속성(화면/자막/오디오/나레이션/CTA), 하단 간단 타임라인. 스타일 선택 영역에 `인기`, `새 스타일`, `내 프리셋`, `브랜드` 탭 포함.
4a. **Trend Studio**: 지역·언어·플랫폼·콘텐츠별 동적 프리셋 카탈로그. 근거·최종 확인일·지원 엔진 버전·권리 요건 표시.
4b. **CTA Studio**: 영상 후반 오버레이/엔드카드/음성 CTA, 플랫폼별 문구·행동 목표·브랜드 요소·URL 관련 메타데이터 편집.
5. **내보내기**: 포맷/품질/저장 위치, 자막 번인 여부, 예상 파일 크기(추정), 렌더 진행률, 실패/재시도.
6. **게시함**: 연결 계정, 플랫폼별 제목·설명·해시태그·공개 범위, 미리보기, 게시 확인, 플랫폼별 성공/실패/예약 상태.
7. **설정**: 언어, GPU 가속, 로컬 파일 캐시, AI 공급자, 개인정보·보관 기간, 연결 계정, 기본 템플릿.

## 4. 영상 입력과 권리 모델 — 출고를 좌우하는 제약

### 4.1. 소스 유형

- A. 로컬 파일(MP4/MOV/MKV 등): 1차 주력, 클립 탐색·음성 추출·렌더 가능.
- B. YouTube URL: 공식 IFrame 플레이어로 재생/탐색 및 시작·종료 시각 후보 저장. **URL만으로 임의 영상의 소스를 다운로드하거나 고품질 변환하는 기능을 보장하지 않음**. 출고 가능한 원본은 사용자가 제공한 파일 또는 허가받은 별도 미디어 소스로 연결.
- C. 직접 관리하는 클라우드 파일: 추후 Google Drive/S3/R2 등 사용자가 접근 권한을 가진 원본 가져오기.
- D. 본인 채널에서 합법적으로 확보한 파일: 사용자 파일 업로드/가져오기. YouTube Studio에서 자신의 업로드 영상 다운로드 또는 Google Takeout 사용 가능(품질 제한 가능).

### 4.2. URL 입력 경험

1. 사용자가 YouTube 링크 입력 → 썸네일·제목·길이·임베디드 플레이어 표시.
2. 플레이어 이동·탐색 → In/Out 마커 지정, 클립 후보 목록 저장.
3. 소스가 아직 없으면 버튼에 `원본 연결 후 제작`이라고 명시. 필요한 시점에 원본 파일 선택.
4. 원본의 타임코드/길이/해시나 사용자 확인으로 매칭하고, 오프셋 차이가 있으면 싱크 교정.
5. 권리 확인과 소스 상태를 프로젝트에 표시; 권리 확인만으로 API 정책 제한이 면제되지는 않음.

**정책 참고(2026-10-22 확인):** YouTube API 개발자 정책은 YouTube 사전 서면 승인 없는 시청각 콘텐츠 다운로드·임포트·캐시·저장을 제한. YouTube IFrame Player API는 플레이/중지/seek 지원. 따라서 URL 처리 UX와 렌더 소스 확보 경로를 분리한다.

## 5. 구간 탐색·추천 엔진

### 5.1. 수동 탐색 (MVP 필수)

- 초 단위/프레임 단위 시작-종료 조정, 클립 추가·삭제, 다중 구간 이어 붙이기.
- 파형, 무음 구간, 장면 전환(가능한 소스에 한함), 자막 단어/문장 클릭하여 탐색.
- 자유 텍스트 메모, 즐겨찾기, 후보 비교(좌/우 또는 순차 프리뷰), 구간 이름 자동 추천.
- 탐색 중인 범위만 반복 재생, 지정 길이(15/30/45/60/90초) 후보 필터링.

### 5.2. AI 후보 추천 (2차)

- 음성 인식 및 타임스탬프, 주제 분할, 침묵/박수/웃음 등 음향 신호, 장면 전환 감지.
- 후보 평가 기준: 첫 2~3초 훅, 핵심 메시지, 독립적 맥락, 결론, 발화 명료성, 쇼츠에 맞는 길이, 중복도.
- 후보 카드에는 `시작~끝`, `길이`, `추천 이유`, `핵심 대사`, `등급(내부 상대 점수)`, `선택/제외/수정` 제시.
- 점수는 조회수 예측이라고 주장하지 않으며 추천 근거를 표시.
- 자동 추천은 원본 파일/접근 가능한 음성·자막이 있을 때 수행. YouTube URL만으로 자유롭게 대본을 확보한다고 가정하지 않음.

### 5.3. 컷 설계

- 단일 연속 구간과 여러 구간 연결을 모두 지원.
- 자동 트림은 문장 중간 절단과 의미 왜곡을 피하도록 주변 맥락을 고려.
- 숏폼 첫 장면 `후킹 텍스트`는 선택형, 사용자 수정 가능.

## 6. 화면 비율·해상도·크롭

- 기본 프리셋: 세로 9:16, 1080×1920, 30fps, H.264/AAC, MP4.
- 추가: 720×1280(경량), 1440×2560(고화질·소스 허용 시), 1:1, 4:5, 16:9.
- 원본 품질 이상 확대 시 `화질 향상이 아닌 업스케일` 경고.
- 화면 채우기 옵션: 자동 인물/화자 추적, 중앙 크롭, 사용자 지정 영역, 배경 블러, 배경 단색/그라데이션, 상하 분할(대화 등).
- 플랫폼별 안전 영역 오버레이: 자막 및 중요한 얼굴/상품을 앱 UI 가림 영역에서 보호. 플랫폼별 버전 관리.
- 빠른 프리뷰는 저해상도 프록시, 최종은 원본 해상도로 재렌더.

## 7. 자막

- 입력 방식: AI 자동 음성 인식, SRT/VTT 업로드, 직접 타이핑, 텍스트 없음.
- 타이밍: 문장·단어 단위 시간 교정, 끌어서 길이 조절, 문장 분할/병합.
- 템플릿: 미니멀, 볼드 숏츠, 단어 하이라이트/가라오케, 뉴스/교육, 브랜드 커스텀.
- 조절: 글꼴(라이선스 적합), 색상·테두리·그림자, 크기, 줄 수, 좌표, 배경, 등장 효과, 화자별 색상, 강조 단어.
- 언어: 한국어/영어 MVP; 번역 자막·다국어 자막은 확장.
- 파일 출력: 영상 내 번인(burn-in) 기본; SRT/VTT 별도 저장 가능.
- 검수: 원문 교정, 화면 밖 텍스트 탐지, 오탈자 검토, 영상 오디오와 싱크 미리보기.

## 8. 나레이션과 사운드

## 8A. Trend Studio — 진화하는 자막·나레이션·편집 프리셋 (v1.1 추가)

### 8A.1. 제품 요구사항

- 기본 탑재 템플릿 몇 개로 고정하지 않는다. 앱 본체를 업데이트하지 않고 온라인 카탈로그에서 신규 스타일을 받아 `선택 옵션`으로 추가한다.
- 스타일은 단순한 자막 색깔뿐 아니라 **자막/타이밍, 폰트, 애니메이션, 편집 리듬, 크롭, 전환, 나레이션 스크립트 톤, TTS 파라미터, 효과음, BGM 믹싱, 후킹 텍스트, CTA**를 묶는 `StyleBundle`로 정의한다. 동시에 각 속성은 개별 변경 가능하다.
- `트렌딩`, `추천`, `최신 등록`, `클래식`, `브랜드`, `내 스타일`로 탐색. 국가/언어/콘텐츠 장르/플랫폼 필터, 짧은 샘플 프리뷰와 실제 적용 프리뷰를 제공한다.
- 자동 업데이트 기본 ON(사용자가 설정에서 OFF 가능). **새 스타일은 라이브러리에 추가할 뿐, 이미 만든 영상/저장 프로젝트의 스타일을 몰래 변경하지 않는다.** 사용자가 선택한 경우에만 적용한다.
- 데이터가 부족하거나 비교가 부정확하면 `트렌딩` 또는 `조회수 상승 보장` 같은 표현을 사용하지 않고 `새로운 스타일` 또는 `추천 스타일`로 표시한다.

### 8A.2. 신호 수집 → 분석 → 제작 → 검증 → 배포

1. **탐색 신호**: 공식 플랫폼 동향/메타데이터, 허가된 레퍼런스, 사용자 자발적 제공 예시, 명시적 사용 동의를 받은 자체 성과 데이터. TikTok Creative Center/조건부 Business Discovery API, YouTube Data API의 `mostPopular` 등의 *허용된 범위*를 조사. 각 소스에 `sourceType`, `region`, `collectedAt`, `accessRights`, `confidence` 보관. 플랫폼에서 확보할 수 없는 데이터는 별도 출처 없이 수집할 수 있다고 가정하지 않는다.
2. **패턴 도출**: 편집 가능한 라이선스/접근 권한이 있는 사례에서 자막의 글자 수·위치·강조 간격, 컷 길이, 도입 후킹, 음성 템포, SFX/무음 리듬 등을 추상화한다. 제3자 영상/음성/템플릿 파일을 복제해 배포하지 않는다.
3. **프리셋 합성**: 렌더 엔진이 지원하는 **선언형 구성**만 출력. AI가 새로운 실행 가능한 코드, 플러그인, 임의 스크립트를 원격 다운로드해 실행하도록 하지 않는다.
4. **자동 검증**: 스키마 검사, 엔진 버전 호환, 설치된 폰트/대체 폰트, 한글·영어 줄바꿈, 플랫폼 안전 영역, 자막 대비/접근성, 페이드/화면 번쩍임, 무음/피크 음량, 9:16/1:1 등 샘플 렌더 스냅샷, CTA 테스트. 라이선스와 모방 위험 검토. 불합격 시 폐기/검토 대기.
5. **배포·철회**: 서명된 스타일 매니페스트/무결성 해시/버전/지원 엔진 버전, 점진적 롤아웃, 장애 시 즉시 철회(kill switch)와 마지막 정상 버전으로 롤백. 캐시된 스타일은 오프라인 사용 가능.
6. **개인화**: 사용자가 명시적으로 동의한 데이터만으로 언어, 국가, 업종/장르, 좋아요/숨기기, 실제 사용 빈도를 기준으로 추천. 새 스타일 발견과 특정 스타일을 강제 적용하는 것은 분리.

**운영 주기 제안:** 신호 수집 매일, 주간 후보 생성 및 자동 검증, 통과한 스타일의 순차 배포, 매월 오래된 트렌드의 추천 강도 감쇠. 이 주기는 제품 설정이며 API 호출 권한·실제 데이터 접근·품질에 따라 변경될 수 있다. `인기`는 관측 가능한 근거/기간을 함께 제시하며 실측 성과를 단정하지 않는다.

**레퍼런스/권리:** 승인되지 않은 플랫폼 대량 스크래핑, DRM 우회, 무단 동영상·음성 다운로드, 저작권 있는 효과음/음악/폰트·상표·크리에이터 고유 요소 복제, 플랫폼이 허용하지 않는 개인화된 데이터 수집을 의존성으로 삼지 않는다. TikTok 상업용 음원은 자체 CML 라이선스의 사용 범위가 있으므로, 숏컷 앱이 해당 음원 자체를 복사해 모든 플랫폼에 자유 재배포할 수 있는 것으로 간주하지 않는다.

### 8A.3. 스타일 모델과 버전

```text
StyleBundle
  id / slug / title / summary / author / category
  sourceEvidence[] (official/permissioned source, region, signal date, confidence)
  status (candidate, validating, active, deprecated, revoked)
  publishedAt / expiresAt? / recommendationScore?
  compatibility (minimumEngineVersion, supportedAspectRatios, TTS features)
  version: semver, hash, signedManifestRef
  subtitlePreset / motionPreset / pacingPreset / audioPreset
  narrationPreset (mode, scriptTone, voicePreferences, speedRange, pauseProfile)
  hookPreset / ctaPreset / assetRequirements / licensePolicy
  previewManifest / sampleMediaLicense

Composition.styleSnapshot = { styleBundleId, version, resolvedParameters, hash }
```

렌더는 `styleSnapshot`의 고정 버전으로 재현 가능해야 한다. 하위 호환 실패/삭제된 템플릿은 프로젝트에서 마지막 정상 스냅샷으로 렌더하고 명확히 안내한다. 사용자가 바꾼 개별 옵션은 템플릿 업데이트보다 우선하며, `스타일 기본값으로 복구`를 제공한다.

- 패턴 예: 한 단어씩 강조, 두 줄 문장형, 발화 타이밍 팝, 질문-정답 리빌, 하이라이트 카드, 인터뷰 화자 구분, 감성 미니멀, 큰 키워드 타이틀.

- 품질: 자막 문구 자동 재작성은 사용자 승인 필요, 실발화 내용과 설명/의역을 구분, 아동/특수 목적 사용 시 깜빡임과 과격한 모션 제한.

### 8A.5. 나레이션 세부 모듈

- 스타일: 대화체, 지식 전달형, 감성 스토리, 다큐멘터리, 드라마틱 후킹, 유머/리액션, 뉴스 요약 등. 단순 목소리 선택이 아니라 **원고 톤/대사 압축/말 속도/쉼표·휴지/억양/원본 오디오 믹스**까지 함께 묶는다.
- 선택 UI: `원본만`, `오프닝만`, `구간 해설`, `전체 교체`, `마무리 CTA`, `사용자 녹음`; 톤별 샘플 청취와 문자 원고 변경 가능.
- 엔진 차이: 지원하지 않는 TTS 음성/감정/SSML은 숨기거나 유사 파라미터로 변환하고 사용자에게 알린다. 공급자 및 생성 음성의 권리·합성 음성 표시 요건 검증.
- 승인: 자동 원고는 원문을 왜곡하지 않는지 사용자 편집/확인, 기존 대사와 충돌 시 자동 덕킹 또는 타임라인 조정.

## 8B. CTA Studio — 클립 마무리 행동 유도 (v1.1 추가)

### 8B.1. 지원 CTA 유형

| 유형 | 적용 방식 | 기본 길이 (수정 가능) |
|---|---|---|
| 빠른 텍스트 오버레이 | 영상 종료 전 화면 하단/중단 안전영역에 문구+아이콘 | 마지막 약 1~3초 |
| 엔드카드(End slate) | 원본 종료 직후 배경·로고·문구·애니메이션이 있는 별도 장면 | 약 2~5초 |
| 음성 CTA | 자연스러운 TTS 또는 직접 녹음으로 구독/방문 요청 | 문장 길이에 따라 자동 산정 |
| 콘텐츠 연계 CTA | `다음 편에서`, `풀버전 보기`, `댓글에 답하기` 등 문맥에 맞게 선택 | 가변 |
| 브랜딩 CTA | 브랜드 로고/채널명/슬로건·끝맺음 템플릿 | 가변 |
| 결합형 | 텍스트 + 엔드카드 + 나레이션 + 가벼운 효과음 | 가변 |

**행동 목표**: 팔로우, 구독, 좋아요, 댓글, 공유, 프로필 방문, 전체 영상 보기, 웹사이트 방문, 제품/예약/쿠폰, 다음 시리즈. CTA를 사용하지 않을 수 있다(`없음` 기본값).

### 8B.2. CTA 설정과 사용자 경험

1. `CTA 사용` 토글 → `목표 선택` → `스타일 선택` → `표시 시간/위치` → `문구` → `로고·음성` → `미리보기`.
2. 템플릿으로 생성된 CTA 문구는 수정할 수 있어야 하며, AI 제안 문구는 절대 자동 승인·자동 게시하지 않는다.
3. CTA는 기존 영상 끝부분에 겹쳐 표시할지, 별도의 엔드카드를 붙일지 선택. **오버레이는 길이를 늘리지 않으며, 엔드카드는 영상 총 길이가 늘어남**을 명시.
4. 사용자가 이미 지정한 종료 시점/중요 대사를 잘라버리지 않는다. CTA 오디오가 대사와 겹치면 타이밍 변경이나 덕킹 제안.
5. 영상 크기·플랫폼별 안전영역/상호작용 UI를 고려해 문구·로고 배치. 작은 글자/낮은 대비/길이 초과를 자동 경고.
6. 계정별 브랜드 키트(로고·채널명·브랜드 컬러·폰트·승인된 링크/핸들/슬로건), 사용자 저장 CTA 템플릿, 기본 CTA 설정.
7. 플랫폼별 CTA 문구 차별화: YouTube `채널 구독`, Instagram `팔로우` 또는 `프로필 방문`, TikTok `팔로우` 등. *영상에 인쇄된 URL/버튼은 자동으로 클릭 가능한 링크가 되지 않는다.* 플랫폼의 실제 링크 위치/지원은 각 공식 기능 및 계정 요건을 확인해 표현.
8. 특정 카테고리/플랫폼에서 스팸성·오인 유도 CTA를 경고하고, 과장된 약속이나 가짜 클릭 UI는 권장하지 않는다.

### 8B.3. 프로젝트 데이터와 렌더

```text
CTAConfig
  enabled / type (overlay, endSlate, voice, combined)
  goal (follow, subscribe, comment, website, fullVideo, etc.)
  position (lastSeconds, afterVideo, customTime)
  durationMs / text / locale / animationPresetId
  brandKitId / logoRef / foreground/background/contrast settings
  narration (script, voiceId, gain, duckOriginalAudio)
  platformOverrides { youtube?, instagram?, tiktok? }
  urlReference? / safeAreaRuleVersion / approvalState
```

- 렌더 파이프라인에 `CTA overlay/append` → `platform-aware safe area` → `TTS mix/ducking` → `total-duration check` 단계를 포함한다.
- 기존 임계 길이/플랫폼 허용 범위를 초과하는 경우 무음/말 끊김 없이 CTA 길이 조정·오버레이 전환·사용자 확인을 제공한다.
- 엔드카드로 늘어난 시간은 출력 예상 길이와 크기를 즉시 다시 계산한다.
- CTA 없이 원본 내용이 자연스럽게 끝나는 미니멀 프리셋도 반드시 제공한다.

### 8B.4. 선택형 성과 검증 (후속)

- CTA 템플릿별 파일 생성→게시 연계 비율과 사용자 선택률을 확인(사용자 동의). 계정 권한 내 실제 성과 지표를 활용한 A/B 추천은 P2로 둔다.
- 외부 링크 클릭/구독 전환 등 추적할 수 없는 지표는 추정 성과로 포장하지 않는다.

### 10.1. 플랫폼 어댑터

- YouTube Shorts: Google OAuth/YouTube Data API의 videos.insert 업로드, 제목·설명·태그·공개 설정, 업로드 결과 URL 저장. 실제 Shorts 분류는 규격/길이와 플랫폼 판단에 따름.
- Instagram Reels: Meta Instagram Platform Content Publishing API; Business/Creator 등 Professional 계정 대상, 미디어 컨테이너 처리/게시 상태 반영.
- TikTok: Content Posting API, creator info 조회, 개인정보 공개 범위 옵션, 명시적 동의, video.publish 승인. 미감사 클라이언트는 비공개 게시 제한과 심사 요구사항이 있으므로 초기에는 파일 저장 또는 승인된 초안 업로드 폴백.
- 확장 후보: Facebook Reels, LinkedIn, X 등은 공식 범위/승인 요건 조사 후.

### 10.2. 게시 UX

- 하나의 클립 → 여러 플랫폼 체크 → 플랫폼별 제목/설명/해시태그/커버/공개 범위 각각 확인.
- 게시 전 `최종 확인` 필수; 렌더와 출판을 자동 연동하지 않음.
- 독립된 플랫폼별 상태: pending / uploading / processing / published / failed / action_required.
- 네트워크 끊김·중복 재전송 방지용 idempotency, 인증 만료 재연결, 실패 플랫폼만 재시도.
- 예약 게시: 2차; 로컬 앱이 종료돼도 예약을 보장하려면 클라우드 작업 실행기와 안전한 미디어 저장이 필요.
- 업로드 자체, 플랫폼 내 처리 완료, 공개 게시 성공을 다르게 표시.

## 11. 데이터 모델 개요

- `Project`: id, name, mode, status, createdAt, updatedAt, defaultPresetId.
- `MediaAsset`: id, projectId, kind, sourceUrl, localPath/cloudRef, rightsInfo, duration, fps, width, height, fingerprint, availability.
- `Transcript`: assetId, language, segments/words, confidence, revision.
- `Clip`: id, projectId, title, sourceId, in/out points, orderedCuts, approvalStatus.
- `Composition`: clipId, aspectRatio, size, cropKeyframes, subtitleStyleId, audioMix, overlays, styleRevision, **styleSnapshot**.
- `Narration`: clipId, mode, script, language, voiceId, generatedMediaRef, approvedAt.
- `RenderJob`: project/clip/revision, preset, state, progress, outputRef, error.
- `PlatformAccount`: provider, accountId, displayName, encryptedCredentialRef, grantedScopes, state.
- `PublishJob`: renderId, provider, accountId, postMetadata, privacy, scheduledAt, state, remotePostId, remoteUrl, error.
- `Template`: scope, subtitle/audio/video defaults, version.
- `StyleBundle`, `StyleVersion`, `TrendSignal`, `StyleEvidence`, `StyleValidation`, `CatalogRelease`: Trend Studio 신호·근거·프리셋·검증·원격 릴리즈 및 철회 상태.
- `CTAConfig`, `BrandKit`: 편집 가능한 마무리 카드/오버레이/음성·플랫폼별 문구, 브랜드 자산.
- 별도 `AuditEvent` 또는 실행 이력으로 변경·업로드·승인을 추적.

프로젝트 원본은 JSON 기반 비파괴 편집 문서로 저장한다. 앱 DB는 로컬 SQLite로 시작하고, 동기화/계정 기능을 도입할 때 서버 Postgres를 병행한다. 파일 경로는 절대 경로만 의존하지 않고 상대 경로/해시/재연결 방식으로 복구한다.

## 12. 기술 아키텍처 제안

```text
Desktop UI (React + TypeScript)
  ├─ Project / Timeline / Preview / Dynamic Style Catalog / CTA Studio
  ├─ Media adapter (Local, YouTube Embed, Authorized Cloud)
  ├─ Editing domain model (cuts, captions, narration, crop)
  ├─ Local worker
  │   ├─ FFprobe / FFmpeg
  │   ├─ Audio waveform / scene detector
  │   ├─ Local STT optional
  │   └─ Frame-accurate render / quality checks
  └─ Cloud API client (optional)
        ├─ OAuth token broker / platform connectors
        ├─ AI transcription / highlight scoring / TTS
        ├─ Trend signal collectors (approved APIs only)
        ├─ Trend analysis / template generator / validator
        ├─ Signed remote style catalog / rollout / revoke
        ├─ Publish worker / retry / statuses
        └─ Settings / templates / team sync (later)
```

- UI와 렌더 엔진 간 계약은 작업 명세(`RenderManifest`)와 상태 이벤트로 분리해 추후 서버 워커에서 같은 조합을 처리할 수 있게 한다.
- AI 서비스는 Provider 인터페이스로 교체 가능하게 한다(사용자 API 키/BYOK 가능성 포함).
- 프로덕션 OAuth 토큰은 운영체제 키체인/암호화된 서버 저장소에 보관. 렌더 로그나 앱 설정 파일에 노출 금지.
- 로컬 렌더링 중 앱 UI 정지 방지: 별도 프로세스와 작업 큐, 과도한 병렬 실행 제한.
- 업로드 시 중계 저장소가 필요한 플랫폼에만 서명된 단기 URL/업로드 파일을 사용하고 보존 기간을 제한.

## 13. MVP 우선순위

### P0 — 먼저 출시해 검증할 필수 기능

1. 데스크톱 셸 + 프로젝트 생성/저장/복원.
2. 로컬 영상과 YouTube 링크 연결, 링크의 프리뷰/타임코드 마커, 원본 파일 매칭.

5. 자동 자막(초기 공급자 하나), 수동 수정, 3~4개 스타일.
6. 나레이션 없는 모드 + 텍스트/TTS 나레이션 추가(초기 공급자 하나) + 원본 음성 혼합.
7. CTA 기본 텍스트 오버레이 + 엔드카드 + 끄기 옵션, 영상 길이·안전영역 미리보기.
8. **선언형 스타일 카탈로그 로딩 엔진** 및 4개 이상 기본 통합 스타일(자막/나레이션 패턴 포함), 선택한 프리셋 버전 고정.
9. MP4 익스포트, 렌더 상태, 실패/취소 처리.
10. YouTube 업로드 1개 공식 통합 (API 접근 요건 확인); 업로드 후 성공 URL 표시.

## 15. 검증 시나리오 및 비기능 요구사항

**사용자 검증**
- 30분 로컬 원본에서 타임코드를 선택해 3개의 서로 다른 숏폼 생성.
- 16:9 원본을 9:16으로 변경해도 인물 얼굴·자막이 가려지지 않음.
- 한국어 발화를 자동 자막으로 만들고 사용자가 특정 단어/타이밍 수정 가능.
- 나레이션을 끄거나 켜도 다른 설정이 유지되고, 자동 덕킹이 적용됨.
- 새 스타일을 원격 배포하면 앱 재설치 없이 목록에 나타나며, 동일 프로젝트의 기존 프리셋 버전·사용자 수정값은 유지됨.
- 만료/철회된 프리셋·오프라인·렌더 엔진 구버전에서 안전한 폴백과 명확한 안내가 동작함.
- 30초 클립 마지막 2초 오버레이 CTA는 총길이가 유지되고, 3초 엔드카드 CTA는 33초가 되며 플랫폼 길이 상한이 재검증됨.
- CTA 텍스트·로고·음성은 안전영역과 대사 싱크에 맞게 표시되고, CTA OFF도 가능함.
- 렌더 실패 후 수정·재시도해도 프로젝트와 기존 성공 파일 보존.
- 업로드는 확인 버튼 없이 시작되지 않으며, 한 플랫폼 실패가 다른 플랫폼의 성공 상태에 영향 주지 않음.
- URL만 제공한 경우 공식 임베드로 탐색은 가능하되 원본 미연결 상태가 명료하게 표시.

**엔지니어링 검증**
- 스트리밍되지 않는 원본 파일과 60fps·VFR·회전 영상·대용량 파일.
- 오디오 없는 파일, 여러 화자, 긴 무음 구간, 여러 언어, 자막이 없는 소스.
- 작은 디스크 공간, 렌더 중 절전/앱 종료, FFmpeg 경로/권한 문제.
- 인증 만료, 승인 취소, 업로드 네트워크 끊김, 중복 게시 재시도.
- 자동 삭제/보존 정책, 기본 텔레메트리 최소화, 사용자 콘텐츠 전송 동의.
- 원격 스타일 매니페스트 변조/서명 실패/임의 코드 삽입/지원하지 않는 플러그인 필드를 안전하게 거부.
- 무단 수집된 레퍼런스, 라이선스 미확인 음원/폰트, 오류가 발생하는 프리셋은 카탈로그에서 게시되지 않음.

## 17. 성공 지표

- 첫 클립까지 필요한 단계/클릭 수 및 소요 시간.
- 트렌드 프리셋 승인 통과율, 신규 스타일 배포→사용률, 오류/롤백률, 지역별 최신성(증거 시각).
- CTA 활성화율, CTA 종류별 제작 완료율, 플랫폼별 CTA 미리보기 수정률.
- 소스 연결 이후 첫 유효 미리보기·렌더 완료율.
- 생성 클립 중 실제 다운로드/게시 비율.
- 유저가 후보 5개 중 하나를 선택하는 비율, 수동 수정 빈도.
- 플랫폼별 OAuth 연결 성공률, 게시 성공률, 중복 게시 사고 0건.
- 전체 작업 시간 중 대기/렌더/사람의 검수 비중.

## 18. 명시적으로 보류할 결정

1. Electron vs Tauri: 렌더·GPU·배포 실험 후 확정. 권장 초기안 Electron.
2. STT/TTS 공급자: 데이터 처리 정책·음질·비용·한국어/영어 정확도 비교 실험 후.
3. AI 후보 추천 로컬 vs 클라우드: 모델 크기 및 사용자 컴퓨터 성능 검증 후.
