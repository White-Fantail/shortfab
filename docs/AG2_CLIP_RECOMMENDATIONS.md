# AG2 · 실제 YouTube 대사 분석 → 자동 클립 추천

2026-10-22 · dev 브랜치 구현 가이드. [로드맵](ROADMAP.md) · [구현 상태](IMPLEMENTATION_STATUS.md).

## 범위 및 한계

사용자는 YouTube URL로 기존 영상을 열고 8단계 Wizard의 **02 클립**으로 이동해 한 번의 분석 버튼으로 대사 기반 추천을 받는다. **실제 AI 구성**은 로컬 whisper.cpp 음성 인식 + 결정적인 전사 기반 규칙(문장 끝·대사 밀도·질문/반전/감정 표현)이다. LLM으로 텍스트를 생성하거나 객관적인 시청률/조회수 점수를 계산하지 않는다. 다른 클립을 자동으로 다운로드·게시하지 않고, 익스포트 및 별도 게시 승인은 기존 경로만 이용한다.

자동 분석 대상은 현재 공개 YouTube URL로 얻을 수 있는 **최초 60분**이다. 영상 길이 제한 또는 접근/DRM/지역/계정 제한 때문에 가져오지 못하는 경우 오류와 직접 클립 만들기 대안을 제공한다. 음성 없는 영상, 드문드문 말하는 영상의 추천은 0~4개일 수도 있다. 이 경우 가짜 5개를 채우지 않는다. 내레이션/음악/CTA 합성과 인물/장면 자동 배치는 AG3~AG6 별도 단계다.

## 준비

macOS 예시:

```bash
brew install yt-dlp ffmpeg whisper.cpp
ffmpeg -version
ffprobe -version
yt-dlp --version
whisper-cli -h
npm install
npm run dev
```

Windows는 `yt-dlp.exe`, `ffmpeg.exe`, `ffprobe.exe`, `whisper-cli.exe`를 PATH에 설정한다. 별도 실행 파일 위치는 `SHORTFAB_YTDLP_PATH`, `SHORTFAB_FFMPEG_PATH`, `SHORTFAB_FFPROBE_PATH`, `SHORTFAB_WHISPER_PATH`로 지정할 수 있다. 앱의 02 클립 화면에서 GGML 다국어 기본 모델(약 148 MB)을 설치한다. 모델 다운로드는 공급자 서버와 통신하지만 원본 비디오/음성/전사는 외부 AI 서버로 전송하지 않는다. 모델 사용량은 사용자 컴퓨터 자원을 소모하며 큰 영상은 분석 시간이 길 수 있다.

## 모델 설치 피드백 보완 (2026-10-22)

기존 02 클립 화면은 설치 중 버튼만 비활성화되고 다운로드 상태는 표시되지 않았습니다. 02 클립·04 자막·고급 편집 모두 같은 설치 패널을 재사용하며 연결 대기/바이트·진행률/검증/설치 완료 및 실패 재시도가 보입니다. 다운로드 중 경과 시간·12초 이상 데이터 미수신 안내·취소를 제공하고 실제 URL/음성 인식 수용은 별도입니다.

## 실제 흐름

1. 기본 '단계별 제작' 화면에서 **YouTube URL**을 넣고 플레이어 길이가 표시되는지 확인한다. 원본을 승인해 **02 클립**으로 이동한다.
2. 음성 인식 언어(자동 감지/한국어/English)를 고르고 **AI 음성 분석 · 클립 자동 추천** 클릭. 다운로드 → 오디오 분리 → whisper.cpp 구간 전사 → 추천/캐시 단계의 진행률 및 취소를 볼 수 있다.
3. 전사에 충분한 대사가 있으면 **최대 8개** 추천 카드가 나온다. 각 카드에는 실제 인식 대사 일부, 제목(첫 대사에서 발췌), 시간 범위와 길이, 추천 이유 및 오른쪽 원본 IFrame에서 재생하는 버튼이 있다.
4. 체크박스로 후보 1개 이상 선택 후 **선택 후보를 클립으로 추가**. 다른 후보도 나중에 선택할 수 있다. 이미 같은 IN/OUT 클립이 있으면 중복으로 추가하지 않는다.
5. 채택된 클립 제목·IN/OUT을 숫자로 수정하거나 아래 **실제 대사로 구간 다듬기** 목록에서 문장별 **IN/OUT**을 클릭해 보정한다. 승인 후 03 화면·04 자막·05 소리·06 CTA·07 검토·08 MP4 기존 흐름을 유지한다.
6. **더 짧게/더 역동적으로**는 캐시된 Whisper 전사만으로 구간을 다시 선별하므로 원본 다운로드와 음성 인식을 반복하지 않는다. **원본 재분석**을 눌렀을 때만 기존 캐시를 건너뛰고 음성을 새로 분석한다. 이전에 추가·수정·승인한 클립은 남는다.

## 분석/캐시 계약

- `electron/main.ts`: `analysis:cached/start/cancel` Electron IPC. 활성 project ID/videoId/길이를 검증하며 다운로드·모델 설치·렌더·게시·저장과 중복 실행이 충돌하지 않게 잠금을 건다.
- `electron/analyze.ts`: `PersonalVideoTask.acquire` 기존 다운로드 캐시 재사용, FFprobe 오디오 유무, 모델 유효성 확인, 처음 60분을 540초 청크로 나누어 `SttTask.transcribeSlice` 실행, 타임스탬프 정규화. 무음은 `no_speech` 결과.
- `src/shared/recommendations.ts`: SRT 파서가 최대 30큐 자막 제한에 영향을 받지 않고 전체 분석을 진행, 9~60초 발화 후보 구성, 겹침/유효성·요약/추천 이유; 가능한 개수만 추천. 짧게/역동적으로 모드는 별도 가중치 적용.
- `userData/analysis`: 원본 videoId/언어/GGML 모델 fingerprint/분석 버전 조합의 로컬 JSON 캐시. 완성 후 임시 파일을 rename으로 교체하고 취소·실패는 임시 파일만 청소한다. private full source path/토큰은 renderer로 보내지 않는다. 시간 제한, 서브프로세스 종료, 진행/취소 흐름을 유지한다.
- `WizardRecord.clips[clipId].steps.clips.proposed`는 새로운 추천을 **실제 프로젝트 클립에 채택했을 때** 기록하며, 사용자 수동 수정/승인 상태는 별도 보존. 후보 목록 자체는 분석 캐시에서 재구성한다.

## 자동 검증

```bash
npm run check
npm run lint
npm test
npm run build
```

`src/shared/recommendations.test.ts`에는 실제 형식 SRT/문장 구간·타임코드·고정 순위·무음/부적절한 요청/짧은 추천 모드 검증을 추가했다. `electron/analyze.test.ts`는 실제 FFmpeg 합성 영상+가짜 yt-dlp와 fake Whisper CLI를 사용해 **외부 YouTube 네트워크 없이** 오디오 추출→전사→추천→캐시 재사용을 확인한다. 이 테스트는 **실제 GGML 모델 인식 정확도나 다양한 실영상의 편집 적합성 증거가 아니다**.

## 한꺼번에 사용자 수용할 시나리오

- 실제 **30분 이상 한국어 발화** YouTube 1건, **영어 발화** 1건으로 클립 3개를 선택, 각 카드에서 구간 재생 → 문장 IN/OUT 조정 → 승인 → 재열기 → MP4 출력 → 파일 길이/소리 확인
- 짧게/역동적으로 추천 전환에서 **전사 재실행 없이 빠르게 카드만 바뀌는지** 확인
- 분석 중 취소·앱 재시작·같은 원본 재시도/모델 또는 언어 변경·다운로드/모델 누락·무음 영상 대응
- 이미 수정한 클립을 재추천이 덮어쓰지 않는지, 오래된 렌더/별도 YouTube 게시 권한이 자동 활성화되지 않는지 확인
- 실제 GGML Korean/English 단어 정확도, 타임코드 ± 1초 정도, 구간의 앞뒤 문장 완결성 및 UI 작은 창 접근성은 **사용자 실기 확인 후 체크**

## 남아 있는 개발/연구

원격 LLM을 사용하기로 명시적 opt-in 한 경우의 2차 후보 정렬과 관련 비용/외부 전사 전송 고지, 영상 장면 전환 시각 키포인트/화자 교체/오디오 없는 게임·풍경 영상의 자동 추천 및 모델 성능 고도화는 미구현이다. 실제 품질을 수용하기 전 AG2 전체 Exit로 표시하지 않는다.
