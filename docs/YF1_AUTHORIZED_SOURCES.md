# YF-1 · 권리자 원본 매칭 (실험적)

상태: **로컬 허가 원본 연결 코드 + CI 검증 완료, 앱 실기·클라우드 공급자·YF-1 Exit 미검증** (2026-10-22).

## 사용자 흐름

1. YouTube 링크를 붙여 공식 플레이어에서 클립 후보 3개를 저장합니다. YouTube 영상 자체는 다운로드하지 않습니다.
2. 권리자·허가 증빙 참조·클립 발췌와 변형 편집 허가 여부를 입력합니다. YouTube 재게시 권한은 별도 체크합니다.
3. 원본 시작 오프셋(원본 시각 = YouTube 시각 + 오프셋)과 권리자 제공 SHA-256 체크섬(선택)을 입력합니다.
4. 파일 선택 대화상자에서 **권리자가 따로 제공한** 미디어 파일을 연결합니다. 로컬 파일은 8 GiB 이하만 허용합니다.
5. 메인 프로세스가 파일 크기, FFprobe 길이, 원본 오프셋, SHA-256, 권리 만료를 확인합니다. 제공된 해시가 다르면 거절합니다.
6. 프로젝트와 로컬 승인 원본 카탈로그에 videoId↔파일 바인딩을 저장합니다. 같은 videoId의 새 프로젝트에서 등록 파일을 자동 매칭합니다.
7. MP4 출력 직전 파일과 이용 권한을 다시 검사하고 YouTube 구간을 원본 시각으로 변환합니다. 게시 전에는 재게시 허가 및 별도 게시 승인을 확인합니다.

## 구현 구조

- `src/shared/sources.ts`: YouTubeReference, RightsGrant, MediaBinding, SourceResolver, SourceResolution 및 시간/허가 검증
- `electron/sources.ts`: 원본 파일 SHA-256, FFprobe 검사, `userData/sources/approved/{videoId}.json` 등록·재연결
- `electron/projects.ts`: 프로젝트 `youtubeBinding` 저장·재열기, 파일 분실·변조·만료 상태
- `electron/main.ts`: 파일 선택, 원본 오프셋을 반영한 FFmpeg 렌더 및 재게시 권한 차단
- `src/App.tsx`: 파일 바인딩, 권리 선언, 허가 만료/상태 표시

**보안:** 파일 경로는 프로젝트 저장소와 Electron 메인 프로세스에만 남습니다. 렌더러 IPC에는 디스크 경로가 없는 바인딩 요약만 반환합니다. YouTube URL에서 무단 미디어 다운로드를 시작하지 않으며, 임의 웹 URL·클라우드 스토리지 토큰을 받아 서버로 요청하는 동작도 없습니다.

**중요한 한계:** 사용자가 기재한 권리자·허가 증빙은 법적 검증 결과가 아닙니다. 파일 해시와 길이는 해당 파일의 무결성을 확인할 뿐, YouTube 동영상과 *내용이 동일하다고 보증하지 않습니다*. 권리자 제공 매핑의 진위, 영상 프레임/오디오 일치, 실제 계약 범위는 별도로 확인해야 합니다.

**익스포트/게시 연계:** 성공한 MP4에는 원본 연결 식별자(`sourceBindingId`)를 함께 묶습니다. 클립 편집값이 같더라도 사용권을 가진 원본을 다시 연결하면 이전 출력의 게시 준비 상태가 무효화됩니다. 게시 전에 현재 바인딩과 출력의 ID를 다시 비교합니다.

## YF-1 Exit 수용 테스트 (아직 미완료)

- [ ] 타인이 촬영했으나 명시적인 재편집 권한을 받은 테스트 YouTube 영상과 별도 제공된 원본 1건 준비
- [ ] URL 탐색 → 클립 후보 3개 저장 → 원본 SHA-256·이용 허가 등록 성공
- [ ] 프로젝트 재열기/새 프로젝트에서 동일 videoId가 파일 재선택 없이 자동 매칭됨
- [ ] 3개 클립을 각각 MP4로 익스포트하고 실제 길이·프레임·오디오 싱크와 해당 YouTube 영상의 동일성을 별도 확인
- [ ] 타 videoId, 다른 SHA-256, 원본 삭제, 잘못된 오프셋, 권리 만료 시 안전하게 차단
- [ ] YouTube 재게시 권한 없이 MP4를 공식 API에 게시할 수 없는지 확인
- [ ] macOS/Windows 개발/패키지에서 임베드·FFmpeg·프로젝트 저장/복원 검증

## 다음 작업

승인된 클라우드 원본 어댑터와 인증·호스트 allowlist·리다이렉트/SSRF 검증, 권리자 videoId↔미디어 fingerprint 확인, 실제 3개 MP4 수용 시험은 아직 미구현/미검증입니다. YF-2는 파트너/권리자 카탈로그에서 파일을 *최초에도 직접 선택할 필요 없이* 자동 취득하는 기능으로 남습니다.
