# UX · 화면/작업 흐름 명세

상위 기준: [PRODUCT_BLUEPRINT.md](PRODUCT_BLUEPRINT.md). 상태: **기본 개인용 YouTube URL→클립→MP4 익스포트 사용자 확인 완료 (2026-10-22)**. Phase 0 및 Phase 1 첫 UI 묶음도 수용. 3개 실제 클립/OS 패키징/예외·경합은 추가 검증. 자막·나레이션·CTA/동적 스타일은 후속이며, YouTube 게시 코드는 있지만 실계정 게시 수용은 미완료. [현황표](IMPLEMENTATION_STATUS.md).

## YouTube 링크에서 시작하는 것이 기본값 (P0 최우선, 2026-10-22)

**주 사용자:** 기존 YouTube 영상을 클리핑하는 사람. **시작 화면은 YouTube URL 입력이 기본**이며 로컬 파일은 보조/테스트다. 개인용 데스크톱에서는 공식 임베드로 구간을 찾은 뒤 공개 영상이 접근 가능하면 yt-dlp/FFmpeg로 MP4를 출력하며, **해당 기본 흐름의 실제 사용자 성공을 확인했다**. 공개 영상이라도 모두 다운로드 가능한 것은 아니다.

- 붙여넣기 → URL 및 videoId 검증 → 공식 임베드로 탐색 → 플레이어 현재 시각과 클립 IN/OUT·타임라인·후보 3개를 저장/재열기. 첫 단계에서 파일 선택을 요구하지 않는다.
- **클립 상태**: \`탐색 가능\`(preview-only), \`사용 권한 확인 필요\`, \`원본 연동 필요\`, \`제작 준비 완료\`, \`제한됨\`, \`연결 끊김\`을 명확하게 표시.
- 렌더 소스 자동 연결: 제작자 제공 자산/승인된 클라우드 파일/소유자 다운로드를 videoId와 매핑. 가능한 경우 **클립에 바로 적용**하고, 수동 파일 선택은 마지막 대안으로 둔다.
- **개인용 로컬 직접 출력:** 공개 영상은 MP4 익스포트 시 yt-dlp로 미디어를 가져와 FFmpeg 인코딩. 사용자 수용 1건 이상 성공(2026-10-22). 접근 불가/제한 영상은 오류를 표시하고 승인 원본 연결 또는 공식 Clips 등 별도 허용 경로를 안내한다. 링크 탐색만 성공했을 때 MP4 출력 성공으로 오표시하지 않는다.
- 다른 사람의 영상이라는 사실만으로 임의 다운로드·재편집·게시가 허가되지 않는다. 저작권/YouTube 콘텐츠 취득 권리와 원본 출처를 별도로 확인한다.
- 실제 원본 확보·권리 검증이 끝나면 기존 편집 UI(9:16·자막·나레이션·CTA·MP4)와 최종 게시 승인을 연결한다.
- **핵심 수용 상태:** 개인용 **URL→클립 선택→MP4 출력 1건 이상 사용자 성공 확인**. 확장 수용 기준인 서로 다른 실제 클립 3개 저장/재열기·MP4 생성 및 권리자/파트너 원본 자동 매칭의 실증은 미완료. 세부: [수용 현황](IMPLEMENTATION_STATUS.md), [YouTube-first 설계](YOUTUBE_FIRST_WORKFLOW.md).

### 현재 구현된 개인용 편집 화면 (2026-10-22)

- **소스:** YouTube URL 입력, 공식 IFrame 탐색. `원본 정보 · 이용 안내`와 고급 권리자·파트너 연결은 같은 스타일의 접힌 패널
- **구간:** 단일 타임라인, 재생/일시정지, 현재 시각 / 전체 길이, IN/OUT 선택 및 클립 후보/해상도 선택. 스크럽 중 오래된 IFrame 시간이 손잡이를 되돌리는 현상은 코드·테스트로 보완
- **결과:** `MP4 익스포트`로 접근 가능한 공개 YouTube 원본을 가져와 9:16 MP4로 저장하는 실제 사용 성공 확인
- **구분:** 자막/나레이션/CTA는 제품 요구사항이지 현 시점의 전체 구현 완료 기능이 아님. 자동 YouTube 업로드도 별도 실제 계정 수용 대기

## Quick Create (기본 사용자 경험)

1. **Source** — YouTube 링크를 입력하면 공식 임베드로 재생/구간 탐색; 로컬 파일을 지정하면 분석/렌더 가능. `미디어 연결됨/원본 연결 필요/지원하지 않음` 상태를 표시.
2. **Find** — 원본 플레이어, 타임라인, 대사/파형(사용 가능한 경우), 시작/종료 마커, 루프, 여러 후보 저장. AI 추천은 후속 추가이며 사용자가 시작/종료 조정 가능.
3. **Frame** — 9:16(기본), 1:1, 4:5, 16:9. 중앙 크롭/직접 이동/배경 블러/인물 추적(후속). 해상도·fps와 플랫폼 안전 영역 프리뷰.
4. **Style** — 자막 ON/OFF, 오탈자·타이밍 수정, 개별 스타일 선택; 나레이션 OFF/도입/구간/전체/마무리, AI 원고 승인, TTS 듣기; 원본·나레이션·BGM 믹싱. Trend Studio 카탈로그에서 스타일을 고르면 전체 기본값을 적용하되 개별 속성 수정 보존.
5. **CTA** — 없음(기본), 오버레이, 엔드카드, 음성/결합; 구독·팔로우·댓글·프로필 방문·풀버전 등 목표, 문구, 타이밍, 위치, 브랜드 키트, 플랫폼별 표현. 엔드카드로 늘어나는 길이 즉시 표시.
6. **Export / Publish** — 원본 연결/해상도/타임코드/자막/오디오/CTA 검증 → 로컬 MP4 익스포트. SNS 게시를 선택한 경우 각 플랫폼의 계정/설명/공개 범위를 표시하고 **별도 승인** 받은 뒤 업로드.

모든 단계에서 중앙 프리뷰에 변경을 반영하고, 뒤로 가도 입력값을 보존합니다.

## Advanced Edit (후속)

- 사용자 요청에 따라 다중 구간 타임라인·자막 단어별 시간·오디오 믹스·크롭 포커스를 노출.
- Quick Create ↔ Advanced Edit 전환이 편집 정보를 삭제하거나 프로젝트 표현을 달라지게 만들지 않음.
- 자동 저장, Undo/Redo, 프로젝트 재열기, 원본 파일 경로 재연결, 선택한 스타일 버전 핀.

## 주요 화면/메시지

| 화면 | 핵심 내용 | 예외/오류 문구 방향 |
|---|---|---|
| 홈 | 최근 프로젝트, 새 프로젝트, 렌더/게시 이력 | 소스 누락 시 재연결 |
| 소스 | 링크·로컬 파일, 임베드, 원본 권한 | `탐색은 가능하지만 원본 연결 후 제작할 수 있어요` |
| 클립 탐색 | 타임라인, 재생, 마커, AI 후보(후속) | 추천 실패 시 직접 지정 유지 |
| 편집 | 세로 프리뷰, 자막/오디오/CTA 탭, 프리셋 | 미지원 스타일 폴백/오프라인 캐시 |
| 익스포트 | 포맷, 해상도, 렌더 진행, 오류 | 디스크 부족·소스 부재·취소·재시도 |
| 게시함 | 게시 승인, 플랫폼별 결과/URL | `업로드 중`, `처리 중`, `게시 완료` 분리 |
| Trend Studio | 새 스타일, 추천, 근거/적용 | `검증된 신규 스타일`과 `트렌딩` 구분 |
| 설정 | 기본값, 언어, 캐시, AI, SNS 계정 | 연결 해제와 자산 삭제 안내 |

## 수용 기준

- YouTube URL만 입력해도 장면 탐색과 마커 저장은 가능하나, 원본 없이는 렌더 버튼이 준비 상태라고 표시되지 않음.
- 30분 원본에서 30초 클립 3개를 각각 편집·저장·재열기·익스포트할 수 있음.
- 기본 자막만 변경해도 다른 클립/나레이션/CTA 설정이 예기치 않게 리셋되지 않음.
- CTA 엔드카드 길이 초과 시 플랫폼 길이 제한 재검증과 선택지 제시.
- 플랫폼 게시에는 어떤 자동화 프리셋을 선택했더라도 별도 사용자 승인이 필요.
## Phase 1 프로젝트 라이브러리 1차 UX

- 프로젝트 선택기에서 최근 프로젝트를 열거나 새로 만들 수 있으며 이름·클립 리스트·현재 선택 클립이 로컬 JSON으로 자동 저장됩니다.
- 클립 후보는 100개까지 생성/선택/삭제할 수 있고 각각 제목·IN/OUT·720p/1080p를 보존합니다. MP4 출력은 **현재 선택한 클립 하나**를 대상으로 합니다.
- 저장된 파일이 없을 때는 비활성 프리뷰·렌더 버튼과 `원본 파일 재연결`을 표시합니다. 다른 파일을 임의로 지정해 이전 클립을 잘못 렌더하지 않도록 길이/크기 검사를 적용합니다.
- YouTube 임베드 링크는 프로젝트에 탐색용 참조로 저장하지만, 아직 IFrame 플레이어의 실제 시간 탐색/마커 연동은 하지 않습니다.
- 편집값은 650ms 디바운스 저장으로 작성됐고, 프로젝트 전환/렌더 직전 미저장 변경을 플러시합니다. OS별 앱 종료 직전 강제 종료·저장 실패를 포함한 통합 테스트가 필요합니다.

## 편집 화면 높이·탭 분리 (Phase 2 UI 수정, 2026-10-22)

- Electron 데스크톱 창 높이 내에서 **왼쪽 입력/클립·중앙 9:16 미리보기+타임라인·오른쪽 결과 패널**의 3열 레이아웃을 유지합니다. YouTube 설정이 늘어나도 전체 문서 높이와 중앙 미리보기 높이가 따라서 커지지 않도록 해야 합니다.
- **좌우 패널을 독립 스크롤**하고, 중앙 미리보기와 타임라인은 항상 같은 화면에 놓습니다. 화면이 낮아져도 미리보기만 가용 공간에 맞춰 축소합니다.
- 오른쪽은 `MP4 익스포트`와 `YouTube 게시` 2개의 접근 가능한 탭(탭 선택 상태 및 tabpanel 연계)을 사용합니다. 익스포트 성공 시 게시 탭으로 이동하지만, 익스포트 진행 및 에러 메시지는 돌아왔을 때 남아 있어야 합니다.
- 기존 게시 메타데이터·연결·이력·업로드/재시도 흐름은 보존합니다. 탭 전환이 게시를 자동 시작하거나 입력값을 초기화하지 않습니다.
- 작은 웹/모바일 화면에서만 1열 스택과 페이지 스크롤을 허용합니다. **검증 항목:** 1280×860, 최소 Electron 850×620, 1024×768, 1920×1080 창에서 프리뷰/타임라인 노출, 좌우 독립 스크롤, 탭 전환 시 입력 보존, 세션·업로드 진행 상태 유지.

## Phase 2 YouTube 공식 게시 UX (2026-10-22, 구현 코드 추가·실계정 검증 대기)

- 성공적으로 선택 클립을 MP4 익스포트한 후에만 같은 프로젝트/클립 구간·해상도에 대한 YouTube 게시 액션이 활성화됩니다. 편집이 바뀌면 다시 익스포트해야 합니다.
- YouTube 연결 버튼은 **시스템 브라우저의 Google 동의 창**을 엽니다. 연결되지 않았거나 환경변수 OAuth 클라이언트 ID가 없으면 게시하지 않습니다.
- 메타데이터에서 제목·설명, 기본 비공개/일부 공개/전체 공개, 아동용 여부(미선택 기본)를 지정합니다. 실제 업로드 전 네이티브 승인 팝업에 이 설정을 다시 보여줍니다.
- 업로드 분할 진행률과 작업 기록, 업로드 완료 후 영상 URL/원격 처리 상태 새로고침을 제공합니다. `processing`을 `published`와 혼동하지 않습니다.
- 서버 통신 실패 시 세션이 있는 작업만 재시도할 수 있으며, 기존 세션이 없거나 만료되면 무조건 새 영상을 만들어 중복 업로드하지 않고 수동으로 YouTube Studio를 확인하도록 안내합니다.
- 초기 기능은 YouTube에 한정됩니다. Instagram/TikTok 직접 게시 및 예약 게시, 자동 계정 정보 표시 등은 아직 구현하지 않았습니다.
